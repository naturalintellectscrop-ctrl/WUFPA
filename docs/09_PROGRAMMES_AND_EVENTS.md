# 09 — Programmes and Events

*Every documented programme, workshop, campaign, competition and festival — and the

## 1. How WUFPA's work is organised on the website

The supplied profile lists WUFPA's work three separate times, under three headings —
"Key Activities" `[P2]`, "Achievements" `[P2]`, and the activity photography `[P8]`–`[P24]` —
with heavy overlap between them. That is normal for a print profile and unusable as an
information architecture.

**Six programme areas** are used instead. This grouping is the agency's synthesis; it is
derived entirely from sourced activity and introduces nothing new.

| # | Programme area | Covers | Route |
|---|---|---|---|
| P1 | Training & Capacity Building | Workshops, master classes, mentorship, labs | `/programmes/training/` |
| P2 | Advocacy, Rights & Anti-Piracy | Copyright, sensitisation, policy, representation | `/programmes/advocacy/` |
| P3 | The Kibanda Initiative | Community screenings | `/programmes/kibanda/` |
| P4 | Distribution & Market Access | Distributors Group, broadcast, MoUs | `/programmes/distribution/` |
| P5 | Competitions & Awards | UCC Regional Film Competition, Awards Gala | `/programmes/competitions/` |
| P6 | International Exposure | Festival delegations, content markets | `/programmes/international/` |

**Why six and not five or eight.** Each area corresponds to a distinct problem WUFPA was
founded to solve ([02 § 2](02_ORGANISATION_PROFILE.md#2-why-wufpa-exists)) and has at least
two independently documented instances. Regional sensitisation, which is by volume the most
photographed activity, sits inside P2 rather than standing alone — because its purpose in
every recorded case was copyright awareness and membership organising, not a separate
programme.

**Why the SACCO is not a seventh programme.** WUFM SACCO is a separate registered entity with
its own identity and its own page (`/sacco/`), not a WUFPA programme. Presenting a financial
cooperative as an association activity would misrepresent the legal relationship
([03 § 8.6](03_BRAND_GUIDELINES.md#86-wufm-sacco-identity)).

project is correcting.

## 9. Recommended event architecture

The requirement is a system WUFPA can maintain with minimal effort that never makes the site
look abandoned (constraint C4).

### 9.1 Event content model

```yaml
title:            string          # required
slug:             string          # required, stable, never changed after publication
status:           upcoming | past | postponed | cancelled   # required
startDate:        date            # required
endDate:          date            # optional
dateUncertain:    boolean         # true where only a year is known
location:
  venue:          string
  district:       string
  subRegion:      enum(6)         # links to /regions/[x]/
programme:        ref → programme # links to /programmes/[x]/
partners:         ref[] → partner
description:      markdown
photos:           ref[] → media
registrationUrl:  url             # optional
contactRoute:     enum            # which enquiry form to route to
```

### 9.2 Status handling — the part that matters

**An event's status is derived from its date at build time, not typed by a human.** This is
the single design decision that prevents the Awards Gala problem from recurring.

| Condition | Rendered as |
|---|---|
| `startDate` in the future | "Upcoming", shown on `/events/` upcoming list and homepage band |
| `startDate` in the past, status `past` | Moved automatically to the past-events archive, tense adjusted in the template |
| `status: postponed` | "Postponed" badge; original date struck through; new date if known |
| `status: cancelled` | "Cancelled" badge, retained for the record — deleting it breaks inbound links |
| `dateUncertain: true` | Year only, or "Date not recorded" |

**The site rebuilds on a schedule** (daily is sufficient) so that an event moves from
"upcoming" to "past" without anyone doing anything
([18_DEPLOYMENT_AND_MAINTENANCE.md](18_DEPLOYMENT_AND_MAINTENANCE.md)). This is a small piece
of engineering that removes the most common way small-organisation sites decay.

### 9.3 Homepage behaviour

The "What's happening" band ([04 § 3.9](04_CONTENT_BIBLE.md#39-news-and-events)) is
conditional:

1. If there are upcoming events → show up to three, titled "What's happening".
2. If there are none → show the three most recent news items, titled "Latest news".
3. If there are neither → the band does not render at all.

No "no upcoming events" message on the homepage. The homepage is not where a visitor should
learn that nothing is planned.

### 9.4 Past events are an asset, not clutter

Past events remain published permanently, with photographs and outcomes. They are the
evidence base for programme pages and the raw material for the activity record. An
association that deletes its past looks younger than it is — and WUFPA's age is one of its
strongest arguments.

## 10. Programme content model

```yaml
title:           string
slug:            string
summary:         string          # one sentence, used on cards
objective:       ref → objective # which of the five core objectives it serves
description:     markdown
partners:        ref[] → partner
regions:         ref[] → region  # where it has been delivered
events:          ref[] → event   # auto-populated by reverse lookup
photos:          ref[] → media
status:          active | historic
```

**The `objective` link is deliberate.** Every programme page can then state which of WUFPA's
five constitutional core objectives `[P1]` it delivers. That closes the loop between what
WUFPA promised at registration and what it has done — an argument no competitor organisation
can make without the same discipline.

## 12. Rules for this section of the site

1. **Every programme claim carries a source.** The tables above are the permitted set.
2. **Never illustrate one programme with another's photographs.** If a programme has no
   photographs, it gets a typographic treatment
   ([03 § 7.5](03_BRAND_GUIDELINES.md#75-when-there-is-no-photograph)).
3. **Never state a frequency that is not evidenced.** "Annual workshops" is sourced `[P2]`;
   "monthly screenings" is not.
4. **Never publish a future date that has passed.** Enforced structurally by § 9.2.
5. **Undated is a legitimate state.** Say "date not recorded" and move on.
6. **Partner names are only attached to events they are documented at.**
7. **A programme with nothing sourced does not get a page.** Six programmes are documented;
   there is no seventh.
